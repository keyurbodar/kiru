No apps. No charts. Just iMessage.

No apps to install, no charts to learn, no jargon.

  • Live price cardsA live price card right in the chat before you commit to anything.
  • You approve everythingEvery order needs your yes — nothing ever moves without it.
  • Memory for moneyAsk “what’s my average cost?” anytime — Kiru remembers your holdings.
  • Cash out anytimeCash out to dollars (USDC) whenever you want.
  • Rich mini-cardsPortfolio mini-cards, live in the conversation.
  • Right region, right startOutside the US only — eligibility is checked up front.
  • Self-custodyYour assets live in your own account, not ours.

05 · Sibyl

Memory with three temperatures.

Kiru’s memory is a Sibyl sidecar: three Python packages, one contract, three tiers that matter.

PackageJob in Kiru
sibyl-memory-cliActivates the sidecar and manages tiers (init, status, upgrades).
sibyl-memory-clientThe engine itself — local SQLite + full-text search, five-tier schema, no embeddings.
sibyl-memory-mcpThe contract Eve speaks — every memory read/write goes through this MCP server.
TierWhat Kiru keeps there
HOTstate/The live quote you haven’t approved yet, and the order in flight.
WARMentities/One record per token: shares held and average cost — your basis.
COLDjournal/Every fill, append-only — the audit trail behind “what did I buy?”

08 · Tech stack

Least custom code wins.

Each layer picks the managed option; custom code lives only in Eve tools.

LayerChoiceWhy
RuntimeEve (TS, Vercel, Photon channel, schedules)Least custom code: agent, channel, and cron ship together.
ChannelPhoton (cloud iMessage numbers, Mini App cards, SMS fallback)Real iMessage numbers without hardware; cards for quotes, SMS when data fails.
WalletBase MCP mcp.base.org → user Base AccountUser custody; approvalUrl flow keeps keys off the server.
MemorySibyl Fly Python sidecar (cli init, client SQLite+FTS5, mcp 8-tool contract)HOT pending quote · WARM positions/basis · COLD fills journal.
MoneyBase MCP Aerodrome plugin (Sugar CLI prepare → send_calls execute · USDC legs)One approval flow: route prepared on-venue, signed in user Base Account. Price comes from the venue quote itself.
