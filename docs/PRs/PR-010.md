# PR-010 — Sibyl search record routes

|Owner|Wave|Label|Complexity|Est|Depends|Branch|Parallel|
|---|---|---|---|---|---|---|---|

## Goal
PR-004 gave the sidecar `recall`/`remember`; the agent still cannot search memory or append to the fills journal. This PR adds the `search` and `record` routes to the Sibyl sidecar so Eve can full-text search past memory and record fills into COLD storage.

## Scope
- Touched: `sibyl-sidecar/main.py` (`search` + `record` routes; `recall`/`remember` unchanged)

## Steps
1. Add the `search` route: full-text query over the client SQLite FTS5 index, returning ranked hits with tier (HOT/WARM/COLD) attached (3 min).
2. Add the `record` route: append-only write to the COLD `journal/` fills history with token, side, shares, price, and timestamp (3 min).
3. Keep `recall`/`remember` behavior from PR-004 unchanged; HOT `state/` (pending quote, in-progress order) and WARM `entities/` (positions/basis) schemas untouched (2 min).
4. Return empty-hit and duplicate-record cases as clean results, not errors, so the agent can narrate them (2 min).
5. Expose both routes through the sidecar MCP contract so Eve calls them like any other memory tool (2 min).
6. Test by seeding the sidecar with a position + fill, confirming `search` ranks the fill for a "what did I buy?" query and `record` appends a new fill retrievable by `recall` (4 min).

## Acceptance
- `search` returns ranked FTS hits with tier labels over seeded memory.
- `record` appends a fill to COLD `journal/` that `recall` can read back.
- `recall`/`remember` and HOT/WARM schemas behave exactly as in PR-004.
